# POLIS v1 Hypotheses

These hypotheses are written before confirmatory LLM runs. Pilot runs may be used to debug code, remove ambiguity, and calibrate mechanism parameters. Confirmatory prompts, scenarios, institutional parameters, metrics, and sample sizes should be frozen before final model runs.

## H1: Prompt governance is incomplete

Prompt-only governance will alter agent behaviour relative to no governance, but will not eliminate the target system-level failure across both environments.

## H2: Executable institutions reduce realized failures

Machine-executable institutions will reduce realized system-level failures more than prompt-only governance under otherwise matched conditions.

## H3: Blunt constraints impose costs

Hard constraint institutions will reduce some failures while increasing either overblocking, unmet legitimate demand, or useful-performance loss in at least some scenario classes.

## H4: Mechanism-matched institutions improve the safety-performance frontier

Mechanisms designed around the structure of the underlying coordination problem will provide a better joint trade-off between safety and useful performance than generic constraints.

For Resource Commons, the primary comparison is hard quota versus congestion pricing.

For Delegation Boundaries, the primary comparison is action-local enforcement versus provenance-aware enforcement.

## Null-compatible interpretation

POLIS is designed so that null or contrary results remain scientifically meaningful. If prompt governance performs as well as executable institutions, if pricing creates no behavioural response, or if provenance tracking offers no measurable advantage, those outcomes should be reported rather than tuned away.
